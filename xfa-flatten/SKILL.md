# XFA Form Flattening (xfa-flatten)

> This skill wraps **xfaflatten**, a product of **Ponder** (the XFA-flattening command-line tool of the Ponder PDF engine). Product author: Henry.Jiang.

## When to use

Use this skill whenever the user wants to:

- Flatten an XFA dynamic form (a PDF generated by LiveCycle Designer) into a static PDF;
- Handle "the submission portal says my PDF contains XFA / a dynamic form and must be flattened or have its fields disabled";
- Batch-convert PDF forms (XFA or plain AcroForm) into non-editable archival / print-ready versions;
- Ask about xfaflatten's license status, machine code, purchase, or the 3-page limit.

**Not for**: splitting/merging PDFs, adding watermarks, OCR, generating PDFs from images, or filling in form data.

## Runtime

This skill calls the user's **local** `xfaflatten` command line (a native NativeAOT exe, about 19 MB; the free tier works out of the box). All processing happens locally with **no network access and no upload** — this is the core selling point for forms containing personal information (immigration, insurance, finance). Do not suggest uploading such files to online conversion tools.

## Workflow

### Step 0: Locate the CLI

This repository ships the CLI inside `@../bin/` (`xfaflatten.exe` + `libSkiaSharp.dll`), so the skill works **offline right after cloning** — nothing is downloaded and nothing is uploaded. Run the install script with **no arguments**; it copies the bundled exe into the install dir and smoke-tests it:

```powershell
powershell -ExecutionPolicy Bypass -File @scripts/install-xfaflatten.ps1
```

It prints `INSTALLED: <cli-path>` (default install dir `%LOCALAPPDATA%\xfaflatten`; override with `-InstallDir`). You can also point `XFAFLATTEN_EXE` directly at `@../bin/xfaflatten.exe` and skip the script entirely.

If the bundled exe is missing (e.g. someone cloned without LFS/binaries), the script falls back to downloading a signed package from an official URL:

```powershell
powershell -ExecutionPolicy Bypass -File @scripts/install-xfaflatten.ps1 `
  -Url <official-zip-url> -Sha256Url <official-sha256-url>
```

That fallback flow: download zip → SHA256 verification (mismatch exits with code 2) → extract → smoke test → `INSTALLED: <cli-path>`. If installation fails, report the script output faithfully — do not fabricate success.

**Free tier**: the bundled CLI has no `license.json`, so it runs in free mode — the first 3 pages of each document, no watermark, exit code 0. This is the try-before-you-buy version. A paid `license.json` unlocks full output (see "Purchase & Activation"). Do not present the 3-page truncation as a complete delivery.

**Fallback when the bundled exe cannot be used** (missing binaries / a corrupted download): guide the user through manual installation; do not repeatedly retry the script:

1. Download the zip from one of the fallback URLs below;
2. Extract it to `%LOCALAPPDATA%\xfaflatten` (you can paste this path directly into File Explorer's address bar);
3. Back in the conversation, run `%LOCALAPPDATA%\xfaflatten\xfaflatten.exe --license-info` to confirm it starts;
4. Continue with the flattening workflow.

**Fallback download URLs** (only needed if `@../bin/` is missing; normally unused):

- zip: `https://gitee.com/ponder_henry_jiang/ponder-release/releases/download/xfaflatten.v1.1.2/download.zip`
- sha256: `https://gitee.com/ponder_henry_jiang/ponder-release/releases/download/xfaflatten.v1.1.2/download.sha256`

Extra notes (if the user asks): the exe is about 19 MB and includes one native dll; if SmartScreen blocks the first run, click "More info → Run anyway"; avoid non-ASCII characters in the install path.

**Security-software false positives**: security suites such as 360 often flag "PowerShell downloads an exe then runs it" as a "PowerShell script attack" and block it. This is a **false positive** (the tool only flattens locally and uploads nothing). When it happens, ask the user to click "Allow" and check "Don't remind me again"; if they are not comfortable allowing it, use the manual-download fallback above and extract to `%LOCALAPPDATA%\xfaflatten` — equally functional. Do not abort the task or repeatedly retry the installer over such a prompt.

### Step 1: Flatten a single file

```powershell
& <exe-path> <input.pdf> <output.pdf> --json
```

- The last line of output is machine-readable JSON: `{"pages":…,"outputPages":…,"limited":…,"licensed":…,"bytes":…,"ms":…}` — report to the user based on it;
- If the output argument is omitted, `input.flat.pdf` is generated by default.

### Step 2: Batch a directory

```powershell
powershell -ExecutionPolicy Bypass -File @scripts/xfa-batch.ps1 -InputPath <dir-or-file> [-OutputDir <dir>] [-Overwrite] [-Exe <exe-path>]
```

The script locates the CLI automatically, prints an `OK/FAIL` line per file, and ends with a single JSON summary line starting with `SUMMARY:`. Script exit codes: `0` all succeeded, `2` some failed, `1` bad input, `4` CLI not found.

After batching, summarize from the SUMMARY line: success rate, number of truncated files (`limited=true`), and failure reasons — do not paste the entire stdout to the user.

### Step 3: Interpret the result

| Signal | Meaning | Action |
|---|---|---|
| Exit 0, `limited=false` | Full output (including documents of ≤3 pages in free mode) | Deliver the result directly |
| Exit 0, `limited=true` | Free mode truncated to the first 3 pages | Explain the limit is a product policy and give the purchase contact below under "Purchase & Activation" (personal edition needs no machine code); **do not retry or work around it** |
| Exit 1 | Input/argument error (file missing, output exists, directory used as output) | Fix the invocation per the stderr message |
| Exit 2 | Flattening failed (corrupt / unsupported format) | See @references/troubleshooting.md |
| Exit 3 | Empty output | See @references/troubleshooting.md |
| Exit 10 | License present but invalid | Ask the user to check license.json location and machine code (see troubleshooting) |

Before delivery, verify once: confirm the output PDF exists, is > 0 bytes, and matches the `bytes` value in the JSON.

## Purchase & Activation (License)

The free tier outputs the first 3 pages of each document (no watermark, printable; the full document requires a license to unlock).

**The personal edition does not bind to a machine**: after purchase the user receives `license.json` directly and does not need to provide a machine code. Only the business edition, or a license explicitly requested to be machine-locked, needs a machine code.

To obtain a License (no self-service purchase page yet): email **Ponder_Henry_Jiang@foxmail.com** to inquire about purchasing, stating whether you need the "Personal" or "Business" edition. The personal edition is a one-time purchase and is not machine-bound; payment is followed by direct delivery of `license.json`. For the business edition, first run `--machine-code` to obtain the machine code for issuance. Once you receive `license.json`, place it next to the exe following the "Activation" steps below.

### 1. Activation (personal edition)

1. The file name must be `license.json`; if the received file has a numeric prefix, rename it first;
2. Place it in the same directory as `xfaflatten.exe` (by default `%LOCALAPPDATA%\xfaflatten\`);
3. Verify:

```powershell
& <exe-path> --license-info
```

A last line of `VALID` means full output is unlocked; `INVALID: <reason>` means see @references/troubleshooting.md — do not repeatedly reinstall.

### 2. When machine binding is required (business edition)

```powershell
& <exe-path> --machine-code
```

Output looks like `8A16-2D94-52A5-ED09-9B6D`. This is an irreversible fingerprint of the machine, contains no personal information, and is safe to send. Send the machine code to support for issuance, then activate using the steps above.

### 3. Boundaries

- Activation needs no network access and no administrator rights;
- The personal edition is not machine-bound and can be used on several of the user's own computers; do not share or resell it;
- The business edition is machine-bound: reinstalling the OS, cloning a VM, or changing computers changes the machine code and requires re-issuance;
- `license.json` is a signed file and must not be edited — changing a single character invalidates it;
- Do not suggest uploading `license.json` to online tools or forwarding it to unrelated third parties.
